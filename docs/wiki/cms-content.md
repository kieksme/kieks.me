# Static Payload content

The public website stays an Astro static build. No browser request uses a Payload API key. Blog articles, public author profiles, legal pages and their metadata are resolved at build time.

## Configuration and publication

Set `PAYLOAD_URL=https://datahub.kieks.me` and `PAYLOAD_BUILD_API_KEY` only in the build runner's private environment/GitHub Actions secrets. The key belongs to a narrow `website-build` service user. Never use a `PUBLIC_` prefix or put credentials in URLs. Without both settings configured, existing local legal Markdown renders unchanged and `/blog` shows an empty index. A partially configured integration fails clearly.

The build client has a fixed `pages`, `posts`, `authors`, `media` endpoint allowlist. Queries always use `draft=false`, explicit published filters, depth zero, bounded pagination and selected fields. Returned drafts, invalid pagination, duplicate IDs or post references to unpublished authors abort the build. Pages are limited to legal content. Existing legal source bodies remain in `src/content/legal/`; CMS legal documents use the slugs `impressum`, `datenschutz`, `agb`. Missing published CMS legal documents fall back individually to the original source. Operators import drafts separately and explicitly publish after review.

Blog URLs are `/blog/<slug>`, author profiles `/blog/autoren/<slug>`. Existing category/tag routes and blog components are reused. Author profiles contain their published articles and optionally an author contact form. A missing publication date is displayed without a fabricated date and omitted from BlogPosting JSON-LD. Author relations are published DTOs; private recipient addresses are never requested or rendered.

## Images and metadata

Only media with `websitePublished=true` are eligible. Downloads use the configured origin's authenticated `/api/media/file/` route, forbid redirects/foreign origins and validate bounded image bytes against MIME/signature. Raster formats PNG/JPEG/WebP/AVIF/GIF are supported; SVG/HTML and unpublished references fail closed. Generated content-hash files go into ignored `public/_cms-media/` and are copied into static output. Each build clears the directory so previously revoked files do not persist. Publish this generated directory with the rest of the new site atomically; retire old deployment artifacts separately if assets were publicly available before revocation.

SEO maps title, description, canonical, robots, full Open Graph and Twitter fields, including static social images. JSON-LD is automatic for Organization/WebSite, BlogPosting, Person and page breadcrumbs where applicable. Script serialization escapes HTML delimiters; only public fields are included. Rich text uses the existing closed renderer and rewrites approved media references to static files. Legal Markdown uses the shared safe Markdown renderer; the trusted local fallback retains its original Astro Markdown rendering.

## Components

`AuthorContact` accepts `authorSlug`, `authorName`, optional `isDemo` (default false). Its native POST action avoids personal data in query strings; JavaScript sends JSON to the intentional public author-contact endpoint. It includes an empty website honeypot, field bounds, submission status and a privacy-policy link. No CMS credential or private recipient address is present. The backend controls origin validation, limits and private inquiry storage; this form does not send email. Use `isDemo` in documentation and never send real test inquiries.

`StructuredData` accepts `items: Record<string, unknown>[]`. It renders one escaped JSON-LD graph. `Metadata` supports per-channel titles/descriptions and image alt text; `Image` serves generated CMS image paths directly without credentialed optimization requests. Existing blog components preserve their layout while linking the article author to the public profile. See `/docs/cms-content` for non-submitting examples and `/docs/editorial-preview` for the separate private editor preview.

## Verification

Run `pnpm check`, `pnpm exec vitest --run`, and `pnpm build`. `cms-content.test.ts` covers endpoint scope, pagination, draft rejection, public image checks, SEO mapping, author visibility, JSON-LD escaping and non-submitting form demos. The private SSR preview remains a separate application; enabling this public build integration does not deploy either website or CMS.

## Editable site sections (services, team, faqs, mcp-projects, navigation)

Expected Payload structure lives in `src/content-model/site-content.ts` (TypeScript types `CmsService`, `CmsTeamMember`, `CmsFaq`, `CmsMcpProject`, `CmsNavigation`). The schema is owned by `kieksme/kieks.me.datahub` (branch `feat/markdown-editor-mcp-drafts`, `docs/editorial/website-schema.md`) and these fields mirror it. All documents need `_status: published` and an optional integer `sortOrder`; only the listed fields are requested (`select[...]`), validated and rendered as **plain text** (no HTML, rich-text fields are ignored). Links must be internal paths, `#fragments` (navigation only), `mailto:` or HTTPS URLs; `/api/...`, `//host`, `javascript:` and the Datahub origin fail the build.

| Collection     | Fields (besides `id`, `_status`, `sortOrder`)                                                                                                   | Rendered on                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `services`     | `title`, `summary`, `href`, `linkText`, `accent` (aqua/fuchsia/yellow/purple); card number follows the order                                    | Home service cards                                        |
| `faqs`         | `question`, `answer`, `placement` (only `home` is shown), `accent`                                                                              | Home FAQ (split into two columns)                         |
| `team`         | `slug` (`andre`/`thomas` selects the bundled portrait), `name`, `position`                                                                      | Home team                                                 |
| `mcp-projects` | `kind` (`mcp-server` or `skill`/`tool`/`product`), `name`, `summary`, `repositoryUrl`, `documentationUrl`, `license`, `npmPackages[]`, `accent` | MCP-Server page, first four servers as home chips         |
| `navigation`   | one document per `key` (`header`/`footer`): `links[]` (`label`, `href`, `children[]`), `secondaryLinks[]`                                       | Header (children = dropdown), footer columns, legal links |

The public build now also renders the home `hero` (page `startseite`, `pageKind=home`: eyebrow, headline lines, lead, validated CTAs) and service `highlights` (matched by service `slug`: `agent-hub`, `ki-mcp`, `cloud-devops`, `entwicklung`, `beratung`). The home page is requested only when `PAYLOAD_SITE_CONTENT=true` (`where[pageKind][in]=legal,home`); without the flag only legal pages are requested and any other page kind is rejected. Highlights replace title and description of the static list; icons, colours and layout stay with the Astro source and are taken by position. Without CMS data the output is byte-identical to the static build (verified by comparing both builds). The private editorial preview (`EditorialContent`, used by `preview/`) additionally renders the other structured Datahub fields: service `number`/`accent`/link, team `profileUrl`, FAQ placement, MCP `npmPackages` and the full navigation tree with `actions`, `secondaryLinks`, `socialLinks` and `footNote`. All links are re-validated and text is escaped. The header `actions` (max. 3, variant `primary`/`secondary`, validated links) replace the static header button, and the footer renders `socialLinks` (max. 8; `icon` must be one of `tabler:brand-github`, `-linkedin`, `-x`, `-xing`, `-mastodon`, `-youtube`, `tabler:mail`, anything else fails the build; `label` is the accessible name) and `footNote`. Because the footer renders link texts and the foot note as HTML, CMS values for those fields are HTML-escaped by the resolver. Social links are only rendered with CMS data, so the static output stays unchanged. Rich text: `faqs.answerRichText` (home FAQ) and `mcp-projects.descriptionRichText` (MCP-Server page, servers and other projects) are rendered as sanitized HTML through the closed Lexical renderer (paragraphs, headings, lists, quotes, links, published images; no raw HTML, scripts or private CMS links, which abort the build). The plain `answer`/`summary` remains the fallback when no rich text exists. `team.bioRichText` (plain `bio` as fallback) appears under the portrait in the home team section, and `services.descriptionRichText` becomes a detail section before the closing call to action on the matching service page (by service `slug`; nothing is rendered when empty). The plain service `description` stays the SEO description and is not shown. Not rendered because the design has no slot for them: `pages.contentRichText` and `sections`. The static ⟦PLATZHALTER D10⟧ note in the team section is part of the Astro source and stays until the team texts are confirmed.

Enable with `PAYLOAD_SITE_CONTENT=true` in the build runner (together with `PAYLOAD_URL`/`PAYLOAD_BUILD_API_KEY`). It is **off by default**, so builds never request collections the CMS does not have yet. Fallback is per section: a missing/empty collection keeps the verbatim static content from `src/content-model/fallback.ts`; without CMS access the output is byte-identical to the previous static build. Known limitation: team members without a bundled portrait are skipped with a build warning until portrait media is wired. Legal pages (`pages`, slugs `impressum`/`datenschutz`/`agb`) work as before; the original Markdown remains the per-document fallback.

## SEO and verification

`scripts/lib/seo-audit.mjs` (run via `node scripts/test-seo-static.mjs` after `pnpm build`, and inside `scripts/test-cms-static-build.mjs`) checks every page for title, description, a single clean canonical, robots (indexable pages `index,follow`; 404, `kontakt-erfolgreich` and `/docs/*` are `noindex` and absent from the sitemap), complete Open Graph and Twitter Card tags (Twitter falls back to the OG values), escaped JSON-LD with Organization + WebSite everywhere, BreadcrumbList on legal pages/articles/authors, BlogPosting on articles and Person on author pages. The fixture build additionally proves that synthetic CMS data never survives a build without CMS access.
